# SPEC 06.5 — Salón de la Fama con datos reales

> **Estado:** Implementado
> **Depende de:** SPEC 06
> **Fecha:** 2026-11-09
> **Objetivo:** Hacer que `/salon` muestre, para cada juego de la tabla `games`, su podio y su TOP 10 reales leídos de la vista `leaderboard` de Supabase.

---

## Por qué existe esta spec

SPEC 06 conectó `/juegos` y el detalle a Supabase, pero dejó fuera el Salón de la Fama a propósito. Hoy `HallOfFame` (componente de cliente) saca las pestañas de `GAMES` (11 juegos), genera 12 filas inventadas con `seededScores` y calcula una fila "TU MEJOR MARCA" ficticia a partir del usuario de `localStorage`. Una partida guardada de ASTEROIDES aparece en el TOP 10 del detalle pero no en el Salón.

La capa de datos ya existe: `getCatalog()` y `getLeaderboard(gameId, limit)` de `lib/catalog.ts`, cacheadas con `"use cache"` y los tags `games` y `game-${id}`, que `saveScoreAction` ya invalida. Esta spec solo conecta el Salón a ellas y retira el código simulado que deja de usarse.

---

## Alcance

**Dentro:**

- **`/salon` lee en servidor** `getCatalog()` y, para cada juego, `getLeaderboard(id, 10)`, y pasa el resultado a `HallOfFame` como prop.
- **Pestañas** solo con los juegos de la tabla `games`, en el orden de `sort_order` (hoy solo ASTEROIDES). El cambio de pestaña sigue siendo en cliente, sin peticiones nuevas.
- **Podio** (oro, plata, bronce) con las filas 1–3 reales. Un puesto sin jugador muestra `—` en nombre, puntuación y fecha.
- **Tabla** con hasta 10 filas reales: rango, jugador, puntuación y fecha (`dd/mm/aaaa`).
- **Estado vacío** de un juego sin puntuaciones: podio con los tres puestos en `—` y, en la tabla, `▸ SIN PUNTUACIONES — SÉ EL PRIMERO_`.
- **Estado de error**: si falla `getCatalog()` o cualquier `getLeaderboard`, `▸ SEÑAL PERDIDA — REINTENTA_` (`SignalLost`) en lugar de pestañas, podio y tabla. El título `SALÓN DE LA FAMA` y el botón `VOLVER A LA BIBLIOTECA` se mantienen.
- **Se quita la fila "TU MEJOR MARCA"** y `HallOfFame` deja de usar `useSession`.
- **Se borra `lib/scores.ts`** (`seededScores`, `seedFor`, `ScoreRow`), que queda sin uso.

**Fuera de alcance (para futuras specs):**

- "TU MEJOR MARCA" real. Necesita Auth y puntuaciones ligadas a usuarios.
- El 404 de la navegación tras guardar (problema conocido de SPEC 06). No se arregla aquí.
- Pestañas para los juegos simulados de `GAMES`, o mezclar datos reales con simulados.
- Inicio con datos reales (`TOP_PLAYERS`, `HOME_STATS`, mini-cards).
- Cargar el leaderboard por pestaña bajo demanda (ruta `/salon?juego=` o Server Action).
- Paginación o más de 10 filas.
- Cambios en el esquema de Supabase, en `lib/catalog.ts` o en `saveScoreAction`.
- Borrar `GAMES` o la partida simulada.
- Limpiar los estilos CSS que queden sin uso (`.tr.you`, `.you-label`).
- Tests automatizados.

## Modelo de datos

Esta spec no introduce tablas, vistas ni funciones de datos nuevas. Reutiliza `Game` (`lib/games.ts`), `LeaderboardRow` y `CatalogResult` (`lib/catalog.ts`) de SPEC 06.

Nuevo tipo de prop para el componente:

```ts
// components/hall-of-fame.tsx
import type { Game } from "@/lib/games";
import type { LeaderboardRow } from "@/lib/catalog";

export type HallEntry = { game: Game; rows: LeaderboardRow[] }; // rows: máx. 10, ordenadas por rank

export function HallOfFame({ entries }: { entries: HallEntry[] }): JSX.Element;
// "use client". Pestaña inicial: entries[0]. Sin entries: solo el mensaje de vacío.
```

`lib/catalog.ts` es `server-only`; el componente solo importa sus **tipos** (`import type`), que no llegan al bundle del cliente.

Estructura de `app/salon/page.tsx`:

```tsx
// Servidor. El título y VOLVER quedan fuera del <Suspense> para que se vean también en el error.
<div className="av-hall fade-in">
  <div className="hall-head">…SALÓN DE LA FAMA…</div>
  <Suspense fallback={null}>
    <HallContent />{" "}
    {/* getCatalog() + Promise.all(getLeaderboard(id, 10)) → <HallOfFame entries> o <SignalLost /> */}
  </Suspense>
  <div className="mt-8 text-center">…VOLVER A LA BIBLIOTECA…</div>
</div>
```

Convenciones:

- Igual que en SPEC 06: solo `lib/catalog.ts` y las Server Actions hablan con Supabase; `HallOfFame` y la página no importan `@supabase/*` ni `lib/supabase/*`.
- La invalidación no cambia: `saveScoreAction` ya llama a `updateTag(\`game-${gameId}\`)`, que es el tag de `getLeaderboard`.

## Plan de implementación

1. **Página de servidor.** `app/salon/page.tsx` pasa a la estructura de arriba: `HallContent` llama a `getCatalog()` y a `getLeaderboard(id, 10)` por juego con `Promise.all`; cualquier `{ ok: false }` → `<SignalLost />`. Mueve el título y el botón `VOLVER A LA BIBLIOTECA` de `HallOfFame` a la página. `npm run build` pasa.
2. **`HallOfFame` con props.** Recibe `entries: HallEntry[]`; las pestañas salen de `entries` y la pestaña inicial es la primera. Deja de importar `GAMES`, `seededScores`, `seedFor` y `useSession`. Quita la fila "TU MEJOR MARCA".
3. **Podio y estados.** Podio con `—` en los puestos sin jugador. Tabla vacía con `▸ SIN PUNTUACIONES — SÉ EL PRIMERO_`. Sin `entries`, solo ese mensaje.
4. **Borrar `lib/scores.ts`.** Comprobar con búsqueda que nada lo importa. `npm run build` pasa.
5. **Verificación con datos.** Con `scores` vacía, revisar `/salon`. Guardar partidas de ASTEROIDES desde `/juegos/asteroides/jugar` y entrar a `/salon` cargando la URL directamente. Para el criterio de 10 filas, insertar puntuaciones de prueba con la publishable key (API REST) y recompilar, porque esos inserts no invalidan la caché.
6. **Limpieza.** Borrar las puntuaciones de prueba de `scores`. `npm run lint` y `npm run build` sin errores.

Reglas transversales:

- No se cambia el esquema. `execute_sql` solo se usa para lecturas de verificación y para borrar las puntuaciones de prueba al final.
- No se usa la `service_role` / secret key.

## Criterios de aceptación

- [ ] `npm run build` y `npm run lint` terminan sin errores.
- [ ] `/salon` muestra una sola pestaña, `ASTEROIDES`; no aparece ningún juego simulado de `GAMES`.
- [ ] Con `scores` vacía, `/salon` muestra los tres puestos del podio con `—` y la tabla con `▸ SIN PUNTUACIONES — SÉ EL PRIMERO_`.
- [ ] Tras guardar una partida de ASTEROIDES y cargar `/salon`, el jugador aparece en el puesto de oro y en la fila `#01` con su puntuación y fecha; plata y bronce muestran `—`.
- [ ] El podio y la tabla de `/salon` coinciden con el TOP 10 de `/juegos/asteroides` (mismos nombres, puntuaciones y orden).
- [ ] Con 11 o más nombres distintos en `scores` para ASTEROIDES, la tabla muestra exactamente 10 filas.
- [ ] No aparece la fila "TU MEJOR MARCA", ni con una sesión iniciada en `/acceso`.
- [ ] Con la URL de Supabase rota (`next dev`), `/salon` muestra `▸ SEÑAL PERDIDA — REINTENTA_` en lugar de pestañas, podio y tabla, y el título y `VOLVER A LA BIBLIOTECA` siguen visibles.
- [ ] `lib/scores.ts` no existe y ningún archivo importa `seededScores`, `seedFor` ni `ScoreRow`.
- [ ] `HallOfFame` y `app/salon/page.tsx` no importan `@supabase/*` ni `lib/supabase/*`.
- [ ] La consola no muestra errores al cargar `/salon` directamente ni al cambiar de pestaña.
- [ ] Inicio y el detalle `/juegos/asteroides` se ven igual que antes.
- [ ] Las puntuaciones de prueba se borran de `scores` al terminar.

## Decisiones

- **Sí:** pestañas solo con los juegos de la tabla `games`. Coherente con `/juegos`, que ya muestra solo ASTEROIDES; no se mezclan datos reales e inventados.
- **No:** mantener los juegos simulados con `seededScores`. Mezclaría datos reales y falsos sin distinguirlos.
- **Sí:** quitar "TU MEJOR MARCA". Sin Auth no hay forma fiable de saber qué marca es "tuya".
- **No:** buscar la marca por `player_name = user.name`. Cualquiera puede usar ese nombre y obligaría a pedir datos desde el cliente.
- **Sí:** 10 filas, igual que el TOP 10 del detalle; ambas pantallas muestran lo mismo.
- **Sí:** podio con `—` en los puestos vacíos. El podio conserva su forma con menos de 3 puntuaciones.
- **Sí:** cargar todos los leaderboards en servidor y pasarlos como prop. Reutiliza `getLeaderboard` cacheada, el cambio de pestaña es instantáneo y no hace falta API nueva.
- **No:** cargar por pestaña bajo demanda. Con un solo juego no compensa la navegación ni el estado de carga extra.
- **Sí:** mismos textos de vacío y error que SPEC 06. Si falla cualquier lectura, `SignalLost` sustituye pestañas, podio y tabla.
- **Sí:** borrar `lib/scores.ts`. Tras SPEC 06 y esta spec queda sin uso.
- **No:** arreglar aquí el 404 tras guardar de SPEC 06. Es otro objetivo; queda como riesgo.

## Riesgos

| Riesgo                                                                                                                                                             | Mitigación                                                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| El 404 de SPEC 06 tras `updateTag` también afecte a `/salon` al navegar justo después de guardar.                                                                  | Fuera de alcance. El criterio de consola se comprueba cargando `/salon` directamente. |
| Una puntuación insertada sin pasar por `saveScoreAction` (REST directo) no invalida la caché y no aparece hasta que caduque (`cacheLife("hours")`) o se recompile. | Aceptado, igual que en SPEC 06. La verificación del criterio de 10 filas recompila.   |
| Con muchos juegos en `games`, la página hace una consulta de leaderboard por juego.                                                                                | Hoy hay uno. Si crece, irá en otra spec (carga por pestaña o una consulta agregada).  |
| Si una sola lectura falla, se pierde todo el Salón aunque los demás juegos hayan cargado.                                                                          | Decisión explícita: un único estado de error, igual que `/juegos`.                    |
